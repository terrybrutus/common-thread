# Private Common Thread Claude service

Live owner-private service: https://common-thread-claude-service.terrbrutus.chatgpt.site

This directory mirrors the Worker source and D1 schema of the separately deployed Sites service. Importing the main game into Caffeine does not rebuild this service. The service has already been deployed independently; the frontend connects to it through `creator/hosted.ts`.

The game opens a top-level private window; sign in with the owning ChatGPT account if asked. After sign-in, the configured game connects automatically; no second generation click is required. A nonce plus exact origin and source-window checks bind the exchange. Personal facts are not placed in URLs. The service allows only same-origin POST requests carrying the Sites-authenticated identity header. It provides no anonymous generation API or browser API key. Only the owner can currently generate; recipients can play a shared puzzle in Caffeine without signing into this service.

The API key is configured as a Sites runtime secret, not in source. No service-access bypass credential is shipped. The owner-private beta has no app-side spending cap, daily/per-person/lifetime quota or timed cooldown. The existing generations table and historical rows are preserved without reading or mutating them for new requests. Anthropic billing controls apply separately; this service does not read or verify the provider cap. Model input remains capped at 60 KB and output at 12,000 tokens; storage requests allow 192 KB. Sign-in, same-origin validation and no automatic retries remain unchanged.

The Worker uses structured JSON output and validates all four groups, 16 unique terms, field lengths and personal provenance before returning. Each personal term needs an exact supporting excerpt from the story. Four personal groups is the default; optional mix requires at least three personal groups and permits at most one related theme. Interest chips never override a rich story. Used-term history encourages variety from unused facts without forcing invention. Provenance checks prevent unsupported terms but cannot prove category fairness or every factual interpretation. Evidence excerpts are stripped from returned puzzle data.

Groups now declare an operation (literal, reverse or fill-blank), four source terms and an optional fixed phrase. Each source is grounded in an internal quotation; transformed tiles are verified against that source using the same operation for all four entries. Reverse does not accept arbitrary missing letters. Fill-blank requires exactly one blank whose substitution reproduces each supported source phrase. Personal wording checks reject terms such as the speaker, the couple, the notes and ambiguous parent references. Date groups must use consistent granularity. The single optional participant-name pair is bounded user data and also labels invitations. Names go to Claude only for personal puzzles; invitation notes remain excluded. Source terms and quotations stay out of returned puzzle records; the public rule field identifies literal, reverse or fill-blank mechanics.

Saved profile JSON also preserves freeform text, reviewed conversation excerpts, participant names and input style without a database migration. The conversation import UI is removed in favor of spoken questions; existing saved excerpts remain compatible. Conversation material is candidate context, not permission to invent completed events or reinterpret plans and jokes as memories. Deterministic regression tests cover transformation and wording gates.

Private POST routes `/api/story/save` and `/api/story/load` use the same trusted Sites identity and same-origin checks, without calling the model or spending a generation. The `stories` table keys profiles by owner and story ID, preserving newer versions when an older copy tries to overwrite them. Generation saves the story before the paid request and updates used-term history after success. Local browser autosave keeps typing immediately, and the connected game saves coalesced edits to cloud automatically. Profile export/import supports backups. The optional `RECOVERED_STORY_JSON` runtime secret seeds an owner's recovered profile on first load without overwriting edits; its value must never enter GitHub. This deployment is owner-private: remove the recovery seed before expanding access to other accounts.

Beta access/parser checks (Node 24): `node --test services/claude/worker/index.test.js` from the game repository. Hosted migrations are generated with Drizzle and applied by Sites during deployment. Do not delete historical ledger rows; beta quota removal does not require a migration. Later schema changes need new migrations.

The provider schema uses one groups array and one entries array with tile/source/evidence fields to avoid the grammar-size HTTP 400 reproduced against the API. Exactly four groups and four entries are checked server-side. Legacy internal fixture shape remains parseable. A real balanced saved-story test completed with four personal groups and a consistent wordplay group; private results are not committed. Haiku uses medium effort and up to 12,000 output tokens. One-edit participant-name normalization requires a unique explicitly supplied participant, retains the original quotation, and does not apply to arbitrary people/places. Provider-error mapping distinguishes configuration, account and transient problems without forwarding raw provider text.

Literal tiles may use a complete shorter phrase only when it occurs at word boundaries inside both the original source and its quoted evidence; the full source/quote must still be grounded in the story. Never permit arbitrary within-word deletions or unsupported abbreviations. Exact source spellings remain valid even if a nearby participant name suggests a possible typo. Draft-validation failures should describe a rejected AI draft, preserve saved answers, and offer the existing generation control rather than implying the user must edit their story.

The shared request/response pipeline allows 12,000 total output tokens (thinking plus JSON) and a 90-second timeout. Real evals showed completed responses exceeding the prior 6,500-token limit. Personal story requests constrain the model to literal groups of meaningful personal facts; common sentence words do not qualify. The engine can turn a verified four-name family group into consistent reversal wordplay and calculates declared reversals exactly before strict validation. Source terms/quotations are preserved. This adds no paid retry or extra AI call. Truncated, refused and malformed responses are distinguished; only a complete board passing every check can be used at a max_tokens boundary.

Played connections are stored per living story only after a group is uncovered in the game, including answers revealed when a round ends. Drafts, examples and incoming friend puzzles do not count. Replays are deduplicated; the latest 80 groups are retained, and up to 40 canonical groups inform Claude's next generation. Three matching underlying terms mark a group familiar, so shuffling, relabeling or reversing the same names doesn't count as a fresh connection. This is a bounded overlap heuristic, not a semantic novelty guarantee.

When all four groups in a new board are familiar, one optional memory question appears without revealing the answers. Skip for now leaves the board playable and mutes that question for the unchanged story, even across reloads. The answer draft autosaves; Add to story & make puzzle appends it to the existing story and makes one explicitly requested generation. Earlier answers are preserved, including when the extra-answer slots are full. No additional model call is used to choose the question, and there are no automatic paid retries. History and optional-question state stay in local autosave and story backups; private cloud also receives them automatically while the story connection is active. Reveals on a friend's separate device are not synchronized.

Cloud saves merge played history with the owner/story-scoped stored copy so an older client cannot erase earlier played groups. Existing timestamp conflict checks remain. No storage migration is required; these are bounded optional fields in the existing profile JSON. Name reversals preserve the original category relationship and explanation instead of changing a mixed family group into parents.

Story follow-ups now open in a centered native dialog, with the background inert, focus on the answer, and a clear Skip for now action (Escape also skips and returns focus to generation). Speak or type directly there; Add to story & make puzzle preserves prior answers and explicitly requests one generation. No puzzle answers appear in the dialog. When no usable board exists, skipping returns to the saved story rather than fabricating a puzzle.

Claude's existing generation response supplies one short follow-up rooted in a supplied memory when information is missing or a remix is familiar. The same call carries the question; there is no separate question-generation call. A typed needs_story result survives both local HTTP and the authenticated private-window bridge. Broad requests for four new categories or oversized multi-question responses fall back to a short story-based question. Technical/auth/billing failures remain ordinary errors. Follow-up prompts and answers are excluded from friend links.

Personal generation now supports true shared-phrase fill-in-the-blank and missing-first-word/missing-last-word groups, alongside literal associations and reversals. Missing halves use complete two-word names/titles actually supplied. True blanks need four full phrases with the same fixed prefix/suffix; the app never invents phrases to force that format. Balanced/tricky favors missing-word variety over repeated reversals. Minimal full source phrases are answer data in casual share links and played history, so hiding half a name does not count as fresh facts. Raw supporting quotations stay private. Editing tiles resets transformation metadata.

Each provenance-valid personal board gets one independent Haiku whole-board audit before release (up to 4,000 output tokens including thinking, 90-second timeout). It checks competing groupings, disjunctive leftovers, unsupported wording and wordplay at balanced/tricky difficulty. Failed audits block drafts; there are no automatic paid regenerations or retries. Personal generation can therefore use two bounded API calls. Missing-story responses skip the audit; study/thematic behavior stays unchanged. The semantic review assists quality and is not proof of unique grouping or perfect factual interpretation.

Conservative narration checks reject unsupported recurring visits, upbringing and market claims in categories/reveals; unsupported decorative clues get neutral hints. If a model quotation is invalid but its unchanged full source appears exactly once at a word boundary in the story, the app selects a verbatim nearby span. It never invents or rewrites source text. Absent or ambiguous sources remain rejected. Saved memories stay unchanged.

The production game connects once when personal creation opens. The private connection automatically processes requests from exact GAME_ORIGINS addresses, with the existing owner sign-in and origin/source/channel checks. There is no second generation button. The named connection is reused for generation and storage; background saves never open another window. A new device may need one normal sign-in. Older game builds also get automatic one-request handoff and close after receiving the result.

Connected story edits debounce to private cloud without calling Claude. The creator loads cloud before uploading local edits, polls every 20 seconds and refreshes on focus. Older four-answer profiles cannot remove a fifth extra answer: shared browser/server merging preserves missing answers and longer extensions. Cloud acknowledgements return the merged profile. Existing cloud extras also reach an older client's generation request. A new computer selects a saved cloud story instead of uploading an empty placeholder. Disconnection/loading failures leave local copies intact and show unsynced status; browser-only text cannot be recovered remotely until that original browser connects or exports a backup.
