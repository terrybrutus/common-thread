# Private Common Thread Claude service

Live owner-private service: https://common-thread-claude-service.terrbrutus.chatgpt.site

This directory mirrors the Worker source and D1 schema of the separately deployed Sites service. Importing the main game into Caffeine does not rebuild this service. The service has already been deployed independently; the frontend connects to it through `creator/hosted.ts`.

The game opens a top-level private window; sign in with the owning ChatGPT account if asked. Press **Make my puzzle** in that window to send the brief to Anthropic. A nonce plus exact origin and source-window checks bind the exchange. Personal facts are not placed in URLs. The service allows only same-origin POST requests carrying the Sites-authenticated identity header. It provides no anonymous generation API or browser API key. Only the owner can currently generate; recipients can play a shared puzzle in Caffeine without signing into this service.

The API key is configured as a Sites runtime secret, not in source. No service-access bypass credential is shipped. The owner-private beta has no app-side spending cap, daily/per-person/lifetime quota or timed cooldown. The existing generations table and historical rows are preserved without reading or mutating them for new requests. Anthropic billing controls apply separately; this service does not read or verify the provider cap. Model input remains capped at 60 KB and output at 5,000 tokens; storage requests allow 192 KB. Sign-in, same-origin validation and no automatic retries remain unchanged.

The Worker uses structured JSON output and validates all four groups, 16 unique terms, field lengths and personal provenance before returning. Each personal term needs an exact supporting excerpt from the story. Four personal groups is the default; optional mix requires at least three personal groups and permits at most one related theme. Interest chips never override a rich story. Used-term history encourages variety from unused facts without forcing invention. Provenance checks prevent unsupported terms but cannot prove category fairness or every factual interpretation. Evidence excerpts are stripped from returned puzzle data.

Groups now declare an operation (literal, reverse or fill-blank), four source terms and an optional fixed phrase. Each source is grounded in an internal quotation; transformed tiles are verified against that source using the same operation for all four entries. Reverse does not accept arbitrary missing letters. Fill-blank requires exactly one blank whose substitution reproduces each supported source phrase. Personal wording checks reject terms such as the speaker, the couple, the notes and ambiguous parent references. Date groups must use consistent granularity. Explicit puzzle-voice participant names are bounded user data, separate from excluded invitation nicknames. Source/operation metadata stays out of returned puzzle records.

Saved profile JSON also preserves freeform text, reviewed conversation excerpts, participant names and input style without a database migration. The conversation import UI is removed in favor of spoken questions; existing saved excerpts remain compatible. Conversation material is candidate context, not permission to invent completed events or reinterpret plans and jokes as memories. Deterministic regression tests cover transformation and wording gates.

Private POST routes `/api/story/save` and `/api/story/load` use the same trusted Sites identity and same-origin checks, without calling the model or spending a generation. The `stories` table keys profiles by owner and story ID, preserving newer versions when an older copy tries to overwrite them. Generation saves the story before the paid request and updates used-term history after success. Local browser autosave handles typing; explicit cloud saves handle edits that have not been used in a new generation. Profile export/import supports backups. The optional `RECOVERED_STORY_JSON` runtime secret seeds an owner's recovered profile on first load without overwriting edits; its value must never enter GitHub. This deployment is owner-private: remove the recovery seed before expanding access to other accounts.

Beta access/parser checks (Node 24): `node --test services/claude/worker/index.test.js` from the game repository. Hosted migrations are generated with Drizzle and applied by Sites during deployment. Do not delete historical ledger rows; beta quota removal does not require a migration. Later schema changes need new migrations.
